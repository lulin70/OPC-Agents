## 〇、背景

v0.3.0 将13个技能收缩到3个核心技能。本文档定义这3个技能的验收标准，作为开发、测试、用户试用的依据。

**核心技能选择理由**:
- **email**: "说一句话发邮件" — 一人公司最高频动作
- **finance**: "说一句话记账" — 一人公司最高频痛点
- **report**: "说一句话生成报告" — 一人公司最高价值交付物

---

## 一、Email 技能验收标准

### 1.1 技能概述

| 项 | 内容 |
|----|------|
| 文件 | `opc_manager/email_skill.py` |
| 核心功能 | SMTP邮件发送、邮件草稿生成、SMTP配置管理 |
| 用户价值 | 替代手动登录邮箱发邮件 |

### 1.2 验收场景

#### 场景 E1: 生成邮件草稿

- **输入**: "帮我给张总写一封项目跟进邮件"
- **预期输出**:
  - 生成邮件草稿（主题 + 正文）
  - 主题简洁明确（≤50字）
  - 正文包含：问候、跟进事项、下一步行动、署名
  - 正文长度 100-500字
- **验收点**:
  - 草稿非空且有意义（非错误信息）
  - 主题和正文都可读
  - 内容与"项目跟进"相关

#### 场景 E2: 发送邮件

- **输入**: "发送邮件给 lulin@example.com 主题项目进展 正文本周完成了三件事"
- **前置条件**: SMTP已配置（`email_config.json` 存在且有效）
- **预期输出**:
  - 调用SMTP发送邮件
  - 返回 `{"success": True, "message": "邮件已发送"}`
  - 收件人收到邮件
- **验收点**:
  - SMTP发送成功率 100%（配置正确时）
  - 发送失败时有友好错误提示（如"SMTP连接失败，请检查配置"）
  - 邮件内容与输入一致（不被篡改）

#### 场景 E3: SMTP配置

- **输入**: 用户在Settings页面配置SMTP（host/port/user/password）
- **预期输出**:
  - 密码加密存储（`encrypt_field`）
  - 配置持久化到 `data/email_config.json`
  - 配置后可立即发送邮件
- **验收点**:
  - 密码不以明文存储
  - 配置文件权限合理（仅用户可读）
  - 配置错误时有明确提示

#### 场景 E4: 错误处理

- **输入**: "发送邮件给 invalid-email 主题测试"
- **预期输出**: 返回 `{"success": False, "error": "邮箱地址格式无效"}`
- **验收点**:
  - 邮箱格式校验（`_validate_email`）
  - 主题长度校验（≤200字）
  - 正文长度校验（≤50000字）
  - 每日发送限额（MAX_DAILY_SENDS=100）

### 1.3 性能验收

| 指标 | 标准 |
|------|------|
| 草稿生成延迟 | < 10s（含LLM调用） |
| 邮件发送延迟 | < 5s（SMTP超时30s） |
| 失败重试 | 最多3次，退避2/4/8s |

## 二、Finance 技能验收标准

### 2.1 技能概述

| 项 | 内容 |
|----|------|
| 文件 | `opc_manager/finance_skill.py` |
| 核心功能 | 记录收入/支出、月度报表、趋势分析 |
| 用户价值 | 替代Excel手动记账 |

### 2.2 验收场景

#### 场景 F1: 记录收入

- **输入**: "帮我记一笔收入3000元来自A公司"
- **预期输出**:
  - 调用 `record_income(amount=3000, source="A公司")`
  - 返回 `{"success": True, "id": "...", "message": "已记录收入 ¥3000.00 (A公司)"}`
  - 数据持久化到SQLite `finance_records` 表
- **验收点**:
  - 金额准确性（3000.00，非3000.0或3000）
  - 数据持久化（重启后仍可查询）
  - 审计日志记录（`AuditLogger.log`）

#### 场景 F2: 记录支出

- **输入**: "记一笔支出500元办公用品"
- **预期输出**:
  - 调用 `record_expense(amount=500, source="办公用品")`
  - 返回 `{"success": True, "message": "已记录支出 ¥500.00 (办公用品)"}`
- **验收点**:
  - 支出类型正确标记（type="expense"）
  - 数据持久化

#### 场景 F3: 月度查询

- **输入**: "这个月收支多少"
- **预期输出**:
  - 调用 `get_monthly_report()` 返回当月收支汇总
  - 包含：income, expense, profit, income_by_category, expense_by_category
- **验收点**:
  - 查询响应时间 < 2s
  - 金额计算准确（income - expense = profit）
  - 分类汇总正确

#### 场景 F4: 错误处理

- **输入**: "记一笔收入-100元"
- **预期输出**: 返回 `{"success": False, "error": "金额必须大于0"}`
- **验收点**:
  - 负数金额被拒绝
  - 零金额被拒绝
  - 非数字金额有友好提示

### 2.3 性能验收

| 指标 | 标准 |
|------|------|
| 记账操作延迟 | < 1s |
| 月度查询延迟 | < 2s |
| 趋势分析延迟 | < 3s |

## 三、Report 技能验收标准

### 3.1 技能概述

| 项 | 内容 |
|----|------|
| 文件 | `opc_manager/report_skill.py` |
| 核心功能 | 周报生成、月报生成、报告导出 |
| 用户价值 | 自动生成经营报告，替代手动写报告 |

### 3.2 ⚠ 依赖问题（需在S1-T2处理）

**当前依赖**:
```python
from opc_manager.finance_skill import get_monthly_report, get_trend  # 核心依赖，OK
from opc_manager.crm_skill import get_customer_stats, get_silent_customers  # 非核心依赖
from opc_manager.task_skill import list_tasks  # 非核心依赖
```

**问题**: report_skill 依赖 crm_skill 和 task_skill（待冻结技能），直接冻结会破坏report功能。

**解决方案（S1-T2执行）**:
- 方案A: 将 crm_skill 和 task_skill 中被引用的方法（`get_customer_stats`, `get_silent_customers`, `list_tasks`）迁移到 report_skill 内部，消除外部依赖
- 方案B: 将 crm_skill 和 task_skill 标记为"半冻结"（代码保留，但不主动维护，仅作为report的依赖存在）
- **PM建议**: 采用方案B（半冻结），避免Sprint 1引入过多重构

### 3.3 验收场景

#### 场景 R1: 生成周报

- **输入**: "帮我生成本周周报"
- **预期输出**:
  - 调用 `generate_weekly_report()` 生成Markdown周报
  - 周报包含：本周完成、待办事项、客户动态、备注
  - 报告保存到 `data/reports/` 目录
- **验收点**:
  - Markdown格式正确（标题/列表/表格）
  - 数据来源真实（从SQLite查询，非硬编码）
  - 报告文件持久化

#### 场景 R2: 生成月报

- **输入**: "帮我生成本月经营报告"
- **预期输出**:
  - 调用 `generate_monthly_report()` 生成Markdown月报
  - 月报包含：财务概况（收入/支出/利润）、收入构成、支出构成、客户动态、趋势分析
- **验收点**:
  - 财务数据准确（与finance_skill查询一致）
  - 环比变化计算正确
  - 趋势图数据合理

#### 场景 R3: 报告导出

- **输入**: "把月报导出为PDF"
- **预期输出**:
  - 调用 `opc_manager/export/exporters/pdf_exporter.py`
  - 生成PDF文件
  - 返回文件路径
- **验收点**:
  - PDF生成成功率 100%
  - PDF内容与Markdown一致
  - 中文显示正常

#### 场景 R4: 空数据处理

- **输入**: 当月无任何收支记录时生成月报
- **预期输出**:
  - 月报正常生成，财务部分显示"暂无数据"
  - 不抛出异常
- **验收点**:
  - 空数据优雅处理
  - 报告结构完整（即使数据为空）

### 3.4 性能验收

| 指标 | 标准 |
|------|------|
| 周报生成延迟 | < 3s |
| 月报生成延迟 | < 5s |
| PDF导出延迟 | < 10s |

## 四、跨技能验收（用户旅程）

### 4.1 旅程 U1: 新用户首次使用

```
打开应用 → Onboarding配置API Key → 输入"帮我记一笔收入5000元"
→ 系统识别意图 → 调用finance_skill → 返回"已记录收入 ¥5000.00"
→ 用户输入"生成本月报告" → 系统生成月报 → 显示报告
```

**验收点**:
- 全程无报错
- 响应时间总和 < 30s
- 用户能理解每步反馈

### 4.2 旅程 U2: 邮件发送全流程

```
配置SMTP → 输入"给张总写跟进邮件" → 生成草稿 → 用户确认
→ 输入"发送给 zhang@example.com" → SMTP发送 → 返回成功
```

**验收点**:
- 草稿可编辑/确认
- 发送前有确认步骤（三贤者投票决策点）
- 发送结果明确反馈
