## 一、验证目标

### 1.1 PMF 早期信号验证

**核心问题**: OPC-Agents 是否真正解决了一人公司经营者的痛点？

| 假设 | 验证方法 | 成功标准 |
|------|---------|---------|
| H1: 用户能独立完成安装配置 | Day 1 观察 | Onboarding 完成率 ≥60% |
| H2: 3 核心技能真实有用 | 每日问卷 + 使用频率 | 使用率 ≥80% + 满意度 ≥3.5/5 |
| H3: 用户愿意继续使用 | 试用结束访谈 | 继续使用意愿 ≥60% |
| H4: 用户愿意推荐 | NPS 问卷 | 推荐意愿 ≥30%（NPS 基线） |
| H5: 用户愿意付费 | 试用结束访谈 | 付费意愿 ≥30% |
| H6: 6 大类型都能找到价值 | 类型分布 + 类型满意度 | 6 大类型各 1-2 名，至少 4 类满意 |

### 1.2 商业指标基线采集

| 指标 | 定义 | 目标（v0.5.0） | 长期目标 |
|------|------|---------------|---------|
| 激活率 | 安装后 7 日内至少使用 3 次 / 安装总数 | 采集基线 | >60% |
| 升级率 | 基础版 → 专业版转化 / 基础版用户 | 采集基线 | >30% |
| 飞轮率 | 达到 FlywheelLevel ≥2 的用户 / 总用户 | 采集基线 | >15% |
| 付费率 | 试用 → 付费转化 / 试用用户 | 采集基线 | >10% |
| NPS | 推荐者% - 贬损者% | 采集基线 | >50 |

### 1.3 体验指标基线采集

| 指标 | 定义 | 目标（v0.5.0） | 长期目标 |
|------|------|---------------|---------|
| 对话自然度 | 用户对对话流畅性的评分（1-5） | 采集基线 | >4.5/5 |
| 结果满意度 | 用户对任务结果的评分（1-5） | 采集基线 | >4.5/5 |
| 主动服务度 | 用户对 AI 主动建议的评分（1-5） | 采集基线 | >4.5/5 |

## 二、用户画像

### 2.1 目标用户特征

| 维度 | 要求 |
|------|------|
| 身份 | 一人公司经营者 / 自由职业者 / 独立顾问 / 内容创作者 / 电商运营 |
| 技术背景 | 非技术背景（不懂 API Key 是什么） |
| 业务需求 | 有邮件沟通、记账、报告生成、任务管理需求 |
| 设备 | Mac 或 Windows 电脑（宽屏，≥1024px） |
| 时间 | 愿意投入 2 周试用，每天至少使用 1 次 |
| 反馈意愿 | 愿意每日填写简单问卷 + 周末接受 30 分钟访谈 |
| 隐私同意 | 同意数据采集（用于产品改进） |

### 2.2 6 大类型详细画像

#### 类型 1: 内容创作者
- **典型职业**: 自媒体作者、独立博主、在线课程创作者、YouTuber
- **业务痛点**: 内容排期混乱、缺乏数据驱动决策、邮件沟通耗时
- **核心场景**: launch_product（产品发布）、content_calendar（内容日历）、digital_product_launch（数字产品上线）
- **关键技能**: email（粉丝邮件）+ report（月度报告）

#### 类型 2: 顾问/教练
- **典型职业**: 商业顾问、人生教练、企业培训师、心理咨询师
- **业务痛点**: 客户跟进困难、方案撰写耗时、反馈收集低效
- **核心场景**: consulting_proposal（咨询方案）、feedback_analysis（反馈分析）
- **关键技能**: email（客户邮件）+ report（咨询报告）+ crm（客户管理）

#### 类型 3: 电商运营
- **典型职业**: 淘宝店主、独立站运营、亚马逊卖家、微商
- **业务痛点**: 订单记账混乱、库存管理、客户复购提醒
- **核心场景**: ecommerce_ops（电商运营）、project_deliverable（订单交付）
- **关键技能**: finance（记账）+ report（经营报告）+ crm（客户复购）

#### 类型 4: 项目交付者
- **典型职业**: 自由设计师、独立开发者、外包工程师、咨询师
- **业务痛点**: 项目进度管理、交付物跟踪、客户验收
- **核心场景**: project_deliverable（项目交付）、write_report（项目报告）
- **关键技能**: task_manager（任务管理）+ report（项目报告）

#### 类型 5: 自由职业者
- **典型职业**: 翻译、写手、设计师、程序员、摄影师
- **业务痛点**: 多项目并行、收入记账、客户沟通
- **核心场景**: write_report（工作周报）、organize_meeting（会议安排）
- **关键技能**: email（客户沟通）+ finance（收入记账）

#### 类型 6: 知识工作者
- **典型职业**: 独立研究员、作家、学者、分析师
- **业务痛点**: 知识整理、研究进度、报告输出
- **核心场景**: write_report（研究报告）、feedback_analysis（反馈分析）
- **关键技能**: report（报告）+ knowledge（知识管理）

### 2.3 排除标准

- ❌ 技术背景过强（开发者/CTO）— 他们不是目标用户
- ❌ 无邮件/记账/报告需求 — 无法验证核心技能
- ❌ 无法本地部署（无 Python 环境）— 需要远程访问方案
- ❌ 不愿提供反馈 — 占用名额但无数据贡献
- ❌ 同类产品深度用户 — 可能带偏产品方向

### 7.3 数据上报（用户主动）

> ⚠️ **2026-07-27 更新**：原 `feedback@promiselink.cn` 是 PromiseLink 官网邮箱，**不属于 OPC-Agents**。
> OPC-Agents 的反馈渠道改为 [GitHub Issues](https://github.com/lulin70/OPC-Agents/issues)。

- 用户可选择是否上报数据到 GitHub Issues（~~原 PM 邮箱 `feedback@promiselink.cn`~~ 已废弃）
- 上报内容：脱敏后的指标数据 + 反馈文字
- 上报方式：通过 GitHub Issues 提交（含截图附件）
- 上报频率：用户主动提交 + 试用结束统一提交

### 7.4 数据隐私保护

| 数据类型 | 处理方式 |
|---------|---------|
| 用户业务数据（邮件/账单/报告） | 仅本地存储，不上报 |
| 用户评分数据 | 脱敏后上报（仅 user_id + rating） |
| 用户反馈文字 | 用户审核后上报 |
| 系统性能数据 | 自动上报（无敏感信息） |
| 错误堆栈 | 自动上报（脱敏） |

## 八、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 招募不足 5 人 | 中 | 高 | 扩大渠道；降低门槛；提供远程访问 |
| 用户无法独立安装 | 中 | 高 | 提供远程协助；优化安装引导；准备 Docker 一键部署 |
| API Key 配置困难 | 中 | 中 | v0.5.0 优化 Onboarding；提供视频指导；Moka AI 备选 |
| 用户反馈 3 技能不够 | 中 | 中 | 记录需求；评估是否解冻 task_manager/crm |
| 用户反馈产品无用 | 低 | 高 | 诚实面对；可能需要重新定义产品方向；触发 v0.6.0 情景 C |
| LLM 后端不稳定 | 中 | 中 | Ollama + OpenAI + Moka AI 三路 fallback |
| 数据采集失败 | 低 | 中 | 埋点测试 + 备用问卷 |
| 用户中途退出 | 中 | 中 | 激励机制（免费 1 年专业版）；保持沟通 |
