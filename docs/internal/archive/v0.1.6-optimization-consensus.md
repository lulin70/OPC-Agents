## 📐 v0.1.6 具体实现方案

### 1. 前端等待体验优化（VETO，Week 1）

**当前问题**：任务执行时页面无明显进度反馈，用户不知道系统在做什么

**实现方案**：
```
阶段1: 请求发起 (0-500ms)
└─ 按钮状态变为loading，禁用重复点击

阶段2: 处理中 (500ms-3s)
└─ 显示进度文案
   "🔍 正在搜索相关资料..."
   "📊 正在分析数据..."

阶段3: 长时等待 (>3s)
└─ 显示进度条 + 预估时间
   "预计还需 15 秒"
   提供"后台运行"选项

阶段4: 完成
└─ 内容显示 + 下载按钮
```

**技术方案**：
- 后端：AsyncTaskExecutor 已支持状态查询，增加阶段状态字段
- 前端：Streamlit `st.status()` 组件实现进度展示
- 可取消：利用现有 `cancel_event` 机制

**验收标准**：
- [ ] 用户提交后1秒内看到进度反馈
- [ ] 每个阶段切换有明确视觉提示
- [ ] 长时间等待（>10秒）显示详细进度
- [ ] 支持取消正在执行的任务

---

### 2. 用户引导（Week 2）

**当前问题**：首次使用不知道从哪开始

**实现方案**：
```
首次访问触发引导：
Step 1: 欢迎页 — "欢迎使用 OPC-Agents，您的AI业务分析助手"
Step 2: 输入区高亮 — "在这里输入您的业务问题"
Step 3: 功能区高亮 — "生成的报告会显示在这里，可以导出或继续追问"

空状态设计：
└─ 无历史记录时显示3个示例问题
   • "分析XX行业趋势"
   • "竞品对比分析"
   • "用户画像研究"
```

**技术方案**：
- Streamlit `st.session_state.onboarding_complete` 控制引导显示
- 示例问题硬编码在前端（5个典型场景）
- 空状态用 `st.info()` + 可点击示例

**验收标准**：
- [ ] 首次用户100%看到引导流程
- [ ] 引导可跳过，且不再重复出现
- [ ] 空状态提供至少3个示例问题
- [ ] 示例问题可一键使用

**当前问题**：搜索结果50%与需求无关

**实现方案（简化版）**：

2. 搜索结果增加相关性评分展示
3. 增加"搜索结果不相关"反馈按钮

**技术方案**：
- `SearchResultProcessor` 增加 TF-IDF 重排序
- 前端显示搜索结果数量和相关性评分
- 反馈按钮记录 bad case 到日志

**验收标准**：
- [ ] 搜索结果前3条相关性 > 70%（人工评测）
- [ ] 零结果查询率 < 10%
- [ ] 搜索响应时间 < 2秒（P95）

### 4. 内容质量增强（Week 3）

**当前问题**：内容质量依赖LLM配置，模板模式质量有限

**实现方案**：
1. 增强质量门禁（v0.1.5已有基础，增加用户反馈维度）
2. 用户可对输出质量打分（👍/👎）
3. 质量不达标时自动重试（最多2次）
4. 质量评分显示

**技术方案**：
- `LLMEnhancedContentGenerator._quality_gate()` 增加评分维度
- 前端增加 👍/👎 按钮，结果存入 `data/feedback/`
- 质量评分显示在交付物头部

**验收标准**：
- [ ] 质量门禁通过率 ≥ 90%
- [ ] 用户反馈收集功能可用
- [ ] 质量不达标自动重试 ≤ 2次
- [ ] 质量评分显示在交付物中

## ⚠️ 风险与假设

### 高风险项

1. **流式输出技术可行性** — Streamlit 不原生支持 SSE，需验证 `st.status()` + 轮询方案
2. **内容质量根因未明确** — 可能是 Prompt 问题或模型 API 问题，Week 1 先做诊断
3. **一人公司资源超载** — 3周工作量对一人团队压力大，需严格控制范围

### 关键假设

- ✅ 用户流失主要因为质量和体验，而非功能缺失
- ⚠️ 用户愿意给反馈（需设计低摩擦反馈机制）
- ⚠️ Streamlit 能支持进度反馈（需技术预研）

### 降级方案

如果3周时间不够：
1. **砍掉搜索优化** — 聚焦质量+体验2个VETO项
2. **砍掉成果物管理** — v0.2.0再做
3. **用户引导简化** — 只做空状态示例，不做完整引导流程
