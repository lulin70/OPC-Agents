### 3.2 P0-1: SearchResultProcessor（搜索结果后处理）

**目标**: 解决"输入Q2营销方案，返回书信格式/写小说/SCI论文"的问题

**位置**: `opc_manager/search_processor.py` (~200行)

**接口设计**:
```python
class SearchResultProcessor:
    def process(self, query: str, raw_results: List[Dict]) -> ProcessedResult:
        """三步处理流水线"""
        
    def _extract_keywords(self, query: str) -> List[str]:
        """从查询中提取核心关键词（去除停用词和功能动词）"""
        
    def _filter_irrelevant(self, keywords, results) -> List[Dict]:
        """规则过滤：标题/摘要必须包含至少一个查询关键词"""
        
    def _score_relevance(self, query, results) -> List[Dict]:
        """简化TF-IDF评分：标题权重×2 + 摘要重叠度"""
        
    def _fallback_to_knowledge_base(self, query) -> List[Dict]:
        """当所有搜索结果都不相关时，返回知识库兜底条目"""
```

**降级策略**: 处理后结果为空 → 返回原始结果（保证不比v3.4更差）

**验收标准**:
- 输入"Q2营销方案"，返回结果中≥60%包含"营销/Q2/方案/增长"等关键词
- 输入"AI Agent框架信息"，返回结果中≥80%包含"AI/Agent/框架"等关键词
- 处理耗时 < 100ms（不应增加明显延迟）

### 3.3 P0-2: LLMEnhancedContentGenerator（LLM增强内容生成）

**目标**: 解决"基准值待测""提升30%"等通用模板问题

**位置**: `opc_manager/llm_content.py` (~300行)

**核心设计 — RAG混合模式**:
```
输入: user_query + search_results
  ↓
Step 1: _gen_skeleton(query) → 结构骨架（复用v3.4的_gen_real_plan逻辑）
  ↓
Step 2: _build_context(search_results) → 搜索参考资料摘要
  ↓
Step 3: _build_prompt(user_query, skeleton, context) → 组装Prompt
  ↓
Step 4: _call_llm(prompt) → LLM生成定制化内容
  ↓ [LLM可用]
输出: 完整的针对性文档
  ↓ [LLM不可用]
Fallback: _fill_template(skeleton, context) → v3.4模板填充模式
```

**Prompt模板设计要点**:
```
你是一个{business_type}领域的专业顾问。
以下是关于"{topic}"的搜索资料：
{context}

请基于以上资料，为一位{user_profile}撰写一份详细的{doc_type}。
要求：
1. 所有指标必须是具体的数字或明确的方法论（禁止"待测量""待填写"）
2. 时间节点必须是具体的日期或周次（禁止"后续""适时"）
3. 风险应对措施必须有具体行动（禁止"加强关注""密切关注"）
4. 必须直接引用搜索资料中的具体信息作为支撑

文档结构骨架：
{skeleton}

请在每个章节下填充具体的、针对性的内容。
```

**降级策略**: LLM API异常/超时/Key无效 → 自动回退到v3.4纯模板模式

**验收标准**:
- 用"AI写作助手 月活5000→10000"背景生成的方案中包含"写作助手""月活""5000""10000"等关键词
- 无"基准值待测""待填写""此处插入"等占位符
- LLM模式下输出长度 > 2000字符（有实质内容）

### 3.4 P0-3: AsyncTaskExecutor（异步任务执行）

**目标**: 解决Streamlit超时崩溃问题

**位置**: `opc_manager/async_executor.py` (~150行) + `frontend/app.py`改造

**核心设计**:
```python
class AsyncTaskExecutor:
    """异步任务执行器"""
    
    TASK_PENDING = 'pending'
    TASK_RUNNING = 'running'
    TASK_DONE = 'done'
    TASK_FAILED = 'failed'
    
    def submit(self, prompt: str) -> str:
        """提交任务，立即返回task_id（不阻塞）"""
        
    def _run_worker(self, task_id, prompt):
        """后台线程：调用TaskEngineV3 + save_deliverable"""
        
    def get_status(self, task_id: str) -> dict:
        """轮询接口：返回status/result/filepath/error"""
        
    def cancel(self, task_id: str) -> bool:
        """取消正在运行的任务"""
```

**前端改造要点**:
```python
# chat_input 回调（旧: 同步阻塞）
# response = execute_task_and_deliver(prompt)

# chat_input 回调（新: 异步非阻塞）
if prompt:
    task_id = async_executor.submit(prompt)
    st.session_state.current_task = task_id
    st.rerun()

# 页面渲染时检查是否有进行中的任务
if st.session_state.get('current_task'):
    status = async_executor.get_status(st.session_state.current_task)
    if status['status'] == 'done':
        # 展示结果 + 下载按钮
        del st.session_state['current_task']
    elif status['status'] == 'running':
        st.status(f"⏳ 正在处理中... (已用时: {status.get('elapsed',0):.0f}s)")
        time.sleep(2)
        st.rerun()  # 轮询刷新
    elif status['status'] == 'failed':
        st.error(f"❌ {status.get('error', '未知错误')}")
```

**验收标准**:
- 提交任务后 < 1s 内看到"已提交"反馈
- 等待过程中页面不崩溃、不断连
- 任务完成后自动展示结果（无需手动刷新）
- 取消功能正常工作

### 3.5 P0-4: SessionContextManager（多轮对话上下文）

**目标**: 支持"基于上次方案，修改第三阶段"

**位置**: `opc_manager/session_context.py` (~150行)

**核心设计**:
```python
class SessionContextManager:
    """轻量级会话上下文（基于session_state）"""
    
    def add_turn(self, user_msg, assistant_response, task_type, filepath):
        """记录一轮完整对话"""
        
    def get_context_for_llm(self, max_turns=5) -> str:
        """构建供LLM使用的上下文摘要（最近N轮）"""
        
    def get_last_result(self) -> Optional[dict]:
        """获取最后一次助手回复（用于迭代修改）"""
        
    def get_history_summary(self) -> str:
        """获取本次会话的完整历史摘要"""
```

**集成到TaskEngineV3**:
```python
# execute() 方法改造
def execute(self, user_input: str, session_ctx: SessionContextManager = None) -> TaskResult:
    # 如果有会话上下文，构建带历史的prompt
    if session_ctx:
        history = session_ctx.get_context_for_llm()
        enriched_input = f"[对话历史]\n{history}\n\n[当前请求]\n{user_input}"
    else:
        enriched_input = user_input
    
    # ... 正常执行流程 ...
    
    # 执行完成后记录到会话
    if session_ctx and result.success:
        session_ctx.add_turn(
            user_input, result.content,
            result.task_type.value, filepath
        )
    
    return result
```

**验收标准**:
- 连续3次调用，第2次能引用第1次的结果
- 会话历史限制在20轮以内（内存安全）
- 刷新页面后历史丢失（已知限制，标注在UI上）

## 7. 风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|-------|------|---------|
| DuckDuckGo持续返回低质量结果 | 高 | 中 | SearchResultProcessor兜底 + 后续考虑换Tavily |
| GLM-4 API Key不可用/额度用尽 | 中 | 高 | Fallback到模板模式（v3.4行为不变） |
| Streamlit轮询导致性能下降 | 低 | 中 | 限制轮询频率(2s) + 最大轮询次数(30次=60s) |
| 多轮对话内存溢出 | 低 | 低 | 限制history为20轮 + 每轮存摘要非全文 |
| 异步线程竞争条件 | 低 | 高 | threading.Lock保护tasks字典 |
