## 一、v4.0 核心变更说明

### 1.1 问题诊断

v3.5的7个技能（意图分析/搜索/分析/内容生成/操作执行/通知/输出）全部属于**"思考层"**：
- 用户说"帮我发邮件" → 系统只能生成邮件草稿 → 用户还得自己复制粘贴发送
- 用户说"帮我记账" → 系统直接说"做不到"
- 用户说"帮我管客户" → 系统没有CRM能力

**场景覆盖率仅21%，6类用户平均满意度仅43%。**

### 1.2 产品定位修正

| 版本 | 定位 | 核心能力 |
|------|------|---------|
| v3.0 | AI辅助的一人公司智能助手 | 聊天+建议 |
| v3.5 | 任务执行与成果交付系统 | 思考+生成文件 |
| **v4.0** | **一人公司全栈运营系统** | **思考+执行+数据闭环** |

### 1.3 v4.0 交付范围

| 优先级 | 技能 | 一句话描述 |
|--------|------|-----------|
| P0 | email | 帮我发邮件，不是帮我写邮件草稿 |
| P0 | finance | 帮我记账，不是帮我生成记账模板 |
| P0 | task_manager | 帮我管待办，不是帮我列待办清单 |
| P0 | crm | 帮我管客户，不是帮我写客户分析报告 |

## 二、功能需求详细定义

### F4.1 邮件管理技能 (email)

#### F4.1.1 功能概述

通过SMTP协议实现真实邮件发送，支持模板、草稿、跟进提醒。一人公司每天5-20封邮件，当前需要切换到邮箱客户端手动操作。

#### F4.1.2 用户场景

| 场景ID | 用户原话 | 当前痛点 | 期望效果 |
|--------|---------|---------|---------|
| EMAIL-01 | "帮我给张总发个跟进邮件，说方案已经改好了" | 需要打开邮箱→选收件人→写正文→发送 | 直接说一句话，邮件发出去了 |
| EMAIL-02 | "帮我给上周见过的3个客户发感谢信" | 需要逐个写，格式不统一 | 自动匹配CRM中的客户，批量发送 |
| EMAIL-03 | "帮我写个报价邮件模板，以后直接用" | 每次都从头写 | 存为模板，下次一键填充 |
| EMAIL-04 | "3天后提醒我跟进王总" | 容易忘记 | 自动创建跟进提醒 |

#### F4.1.3 功能规格

| 功能项 | 规格 | 优先级 |
|--------|------|--------|
| SMTP发送 | 支持QQ邮箱/163/Gmail/自定义SMTP | P0 |
| 邮件模板 | 创建/使用/管理邮件模板，支持变量替换 | P0 |
| 草稿箱 | 保存未发送邮件，支持编辑后发送 | P1 |
| 跟进提醒 | 基于CRM客户创建定时提醒 | P1 |
| 批量发送 | 从CRM筛选客户批量发送 | P2 |
| 邮件历史 | 查看已发送邮件记录 | P1 |

#### F4.1.4 技术约束

- SMTP配置存储在`data/email_config.json`，密码AES加密
- 邮件历史存储在`data/email_history.jsonl`
- 邮件模板存储在`data/email_templates/`
- 单次发送超时30秒，重试3次
- 单日发送上限100封（防滥用）
- 邮件正文最大50KB

#### F4.1.5 安全需求

| 安全项 | 规格 |
|--------|------|
| 密码存储 | AES-256加密，密钥从环境变量读取 |
| 发送审计 | 每封邮件记录到AuditLogger |
| 收件人校验 | CRLF注入过滤（已有） |
| 附件限制 | 禁止发送可执行文件(.exe/.bat/.sh) |
| 频率限制 | 同一收件人1小时内最多3封 |

### F4.2 财务记账技能 (finance)

#### F4.2.1 功能概述

一人公司最基本的需求：知道赚了多少、花了多少、还剩多少。当前完全缺失，用户只能用Excel手动记账。

#### F4.2.2 用户场景

| 场景ID | 用户原话 | 当前痛点 | 期望效果 |
|--------|---------|---------|---------|
| FIN-01 | "帮我记一笔收入，张总付了3000元咨询费" | 需要打开Excel手动填写 | 一句话完成记账 |
| FIN-02 | "帮我记一笔支出，买了200元的设计素材" | 容易忘记记，月底对不上 | 一句话完成记账 |
| FIN-03 | "这个月赚了多少花了多少" | 需要手动汇总Excel | 自动生成月度报表 |
| FIN-04 | "下个月15号要报税，提醒我" | 经常错过报税日期 | 自动提醒 |
| FIN-05 | "帮我看看最近3个月的收入趋势" | 需要手动做图表 | 自动生成趋势分析 |

#### F4.2.3 功能规格

| 功能项 | 规格 | 优先级 |
|--------|------|--------|
| 记账-收入 | 金额/来源/分类/日期/备注 | P0 |
| 记账-支出 | 金额/用途/分类/日期/备注 | P0 |
| 分类体系 | 预设15个一人公司常用分类 | P0 |
| 月度报表 | 收入/支出/利润/分类占比 | P0 |
| 报税提醒 | 增值税/个税关键日期提醒 | P1 |
| 趋势分析 | 近N月收入/支出/利润趋势 | P1 |
| 年度汇总 | 年度收入/支出/利润/税务 | P2 |

#### F4.2.4 数据模型

```
records表:
  id          TEXT PRIMARY KEY
  type        TEXT  -- "income" | "expense"
  amount      REAL
  category    TEXT
  source      TEXT  -- 收入来源/支出用途
  date        TEXT  -- ISO格式
  note        TEXT
  created_at  TEXT

categories表:
  id          TEXT PRIMARY KEY
  type        TEXT  -- "income" | "expense"
  name        TEXT
  icon        TEXT
```

#### F4.2.5 预设分类

| 咨询费 | 工具订阅 |
| 培训费 | 办公设备 |
| 产品销售 | 差旅交通 |
| 课程收入 | 设计素材 |
| 广告分成 | 营销推广 |
| 版税/授权 | 税费 |
| 其他收入 | 通讯网络 |
| | 其他支出 |

### F4.3 待办管理技能 (task_manager)

#### F4.3.1 功能概述

一人公司没有项目经理，所有事情都靠自己记。当前系统无法管理待办，用户需要额外使用Todoist/滴答清单等工具。

#### F4.3.2 用户场景

| 场景ID | 用户原话 | 当前痛点 | 期望效果 |
|--------|---------|---------|---------|
| TASK-01 | "帮我记一下明天要交方案给张总" | 需要切换到待办App | 一句话创建待办 |
| TASK-02 | "今天还有什么没做完的" | 需要打开待办App查看 | 直接问系统 |
| TASK-03 | "方案已经交了，标记完成" | 需要手动勾选 | 一句话完成 |
| TASK-04 | "帮我按优先级排列这周的任务" | 需要手动排序 | 自动排列 |
| TASK-05 | "每天早上9点提醒我今天要做什么" | 需要设闹钟 | 自动提醒 |

#### F4.3.3 功能规格

| 功能项 | 规格 | 优先级 |
|--------|------|--------|
| 创建待办 | 标题/描述/优先级/截止日期/标签 | P0 |
| 完成待办 | 标记完成+完成时间 | P0 |
| 查看待办 | 按日期/优先级/状态筛选 | P0 |
| 优先级 | P0紧急/P1重要/P2普通/P3低 | P0 |
| 截止提醒 | 到期前1天/1小时提醒 | P1 |
| 每日摘要 | 每日待办清单汇总 | P1 |
| 周报生成 | 本周完成/未完成/下周计划 | P2 |

#### F4.3.4 数据模型

```
tasks表:
  id          TEXT PRIMARY KEY
  title       TEXT
  description TEXT
  priority    INTEGER  -- 0=紧急 1=重要 2=普通 3=低
  status      TEXT  -- "pending" | "in_progress" | "done" | "cancelled"
  due_date    TEXT  -- ISO格式, 可空
  tags        TEXT  -- 逗号分隔
  created_at  TEXT
  completed_at TEXT  -- 可空
```

### 3.1 数据安全

| 需求ID | 规格 | 验收标准 | 状态 |
|--------|------|---------|------|
| SEC-4-01 | 所有敏感数据(邮箱密码/客户电话)AES加密存储 | 明文不出现在磁盘上 | ✅ 已实现 |
| SEC-4-02 | SQLite数据库文件权限0600 | 其他用户不可读 | ✅ 已实现 |
| SEC-4-03 | 邮件发送/记账/客户变更全部审计日志 | AuditLogger记录完整 | ✅ 已实现 |
| SEC-4-04 | 客户数据导出需二次确认 | 防止误操作泄露 | ✅ 已实现 |

### 3.2 外部技能安全（SEC-5）

| 需求ID | 规格 | 验收标准 | 状态 |
|--------|------|---------|------|
| SEC-5-01 | 外部技能运行在安全沙箱中，进程级隔离 | 外部技能无法访问主进程内存/文件 | ✅ 已实现 |
| SEC-5-02 | MCP服务器必须使用HTTPS协议连接 | 非HTTPS连接请求被拒绝 | ⏳ 待实现 |
| SEC-5-03 | 外部技能安装前需用户确认权限 | 未确认的技能无法安装 | ✅ 已实现 |
| SEC-5-04 | 信任等级检查，L0等级技能禁止安装 | 低信任技能被拦截 | ✅ 已实现 |
| SEC-5-05 | 外部技能网络访问需白名单授权 | 未授权域名请求被拦截 | ✅ 已实现 |
| SEC-5-06 | 外部技能操作审计日志完整 | 所有操作可追溯 | ⏳ 待实现 |

### 3.3 性能

| 需求ID | 规格 | 验收标准 |
|--------|------|---------|
| PF-4-01 | 记账操作响应<1秒 | 本地SQLite写入 |
| PF-4-02 | 邮件发送<10秒(含SMTP连接) | 正常网络条件下 |
| PF-4-03 | 客户查询<500ms | 1000条记录以内 |

### 3.4 可靠性

| 需求ID | 规格 | 验收标准 |
|--------|------|---------|
| REL-4-01 | SQLite WAL模式，写入不阻塞读取 | 并发安全 |

### 4.1 external_skills 表

```
external_skills表:
  id              TEXT PRIMARY KEY

  description     TEXT
```

## 六、验收标准

### 6.1 功能验收（SMART）

| 验收项 | 指标 | 测量方法 |
|--------|------|---------|
| "帮我发邮件给张总" | 邮件真实发出 | 收件箱收到邮件 |
| "帮我记一笔收入3000" | 记录写入数据库 | SQLite查询确认 |
| "今天有什么待办" | 返回当日待办列表 | 列表非空且正确 |
| "帮我查张总的联系方式" | 返回客户档案 | 信息完整准确 |
| 邮件模板变量替换 | 变量100%替换 | 无{variable}残留 |
| 月度报表 | 收入/支出/利润计算正确 | 与手动计算一致 |

### 6.2 质量门禁

| 门禁 | 标准 |
|------|------|
| 零占位符 | 输出中无"待补充"/"请根据实际"等占位符 |
| 审计完整 | 所有写操作有AuditLogger记录 |
| 测试覆盖 | 每个技能≥10个单元测试 |
| 安全合规 | 敏感数据加密，路径校验通过 |
