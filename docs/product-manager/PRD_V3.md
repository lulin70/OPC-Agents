## 一、需求背景与三层分析

### 1.1 Phase 2 完成状态回顾

```
✅ 已完成 (v2.2.0):
├── 6种人格变体 (YAML配置驱动)
├── BusinessTypeDetector V2 (100%准确率)

```

### 1.2 三层需求挖掘

**Layer 1: 表面需求（用户说什么）**
> "能不能有个网页界面？现在只能用代码调用太不方便了"
> "能帮我对接小红书数据吗？手动复制太累了"
> "检测准确率还能再提高吗？有些复杂句子识别不对"

**Layer 2: 真实需求（用户要什么）**
> 用户需要一个**可交互的Web界面**来降低使用门槛，需要**外部数据源自动接入**来提升效率，需要**更智能的LLM辅助**来处理边界case

**Layer 3: 本质需求（用户为什么）**
> **本质：从"开发工具"进化为"产品"**
> - 降低技术门槛 → 扩大目标用户群（非开发者也能用）
> - 数据自动化 → 提升效率10x（替代手工操作）
> - LLM增强 → 从规则引擎升级为AI原生应用
> - 数据持久化 → 支持多设备同步 + 历史分析
> - CI/CD → 工程化保障产品质量

## 二、功能需求详细定义

### 2.1 P0 核心需求（必须实现）

#### F3.1 Web交互界面

**需求描述**：提供基于浏览器的交互界面，支持对话式操作和可视化展示

**用户故事**：
> **作为** 一人公司创业者，
> **我希望** 通过浏览器访问OPC-Agents，用自然语言对话完成任务，
> **以便** 我不需要写代码就能使用所有功能。

**功能子项**：

| 子项ID | 名称 | 描述 | 验收标准 |
|--------|------|------|---------|
| F3.1.1 | 对话界面 | 类ChatGPT的聊天式UI，支持Markdown渲染 | 支持6种人格风格展示；消息延迟<500ms(P95) |
| F3.1.2 | 业务类型选择器 | 注册/首次使用时选择主业务类型 | 6种类型卡片展示；选择后激活对应人格 |
| F3.1.3 | 场景执行面板 | 展示工作流进度和交付物 | 进度条实时更新；交付物可下载(Excel/PDF/MD) |
| F3.1.4 | 飞轮仪表盘 | 可视化飞轮等级和5维健康度评分 | 环形图+雷达图；升级建议卡片 |
| F3.1.5 | REST API | 后端API接口，供前端调用 | OpenAPI/Swagger文档；全部接口有认证 |
| F3.1.6 | 用户会话管理 | 多会话历史记录 + 搜索 | 最近50条会话；支持按关键词搜索 |

#### F3.2 LLM深度集成

**需求描述**：实现`_detect_by_llm()`存根，引入大语言模型增强检测能力

**用户故事**：
> **作为** 使用复杂表达的用户，
> **我希望** 系统能理解我含糊的描述并正确判断我的业务类型，
> **以便** 不需要记住特定的关键词也能获得精准服务。

**功能子项**：

| 子项ID | 名称 | 描述 | 验收标准 |
|--------|------|------|---------|
| F3.2.1 | LLM服务抽象层 | LLMService类，支持多后端切换 | 支持OpenAI/本地Ollama/Mock；切换配置化 |
| F3.2.2 | 智能检测增强 | 实现_detect_by_llm()方法 | 复杂句准确率≥90%（vs当前关键词匹配70%） |
| F3.2.3 | 混合检测策略 | 关键词优先 + LLM兜底的双层策略 | 关键词命中时<100ms；LLM兜底时<2s |
| F3.2.4 | Prompt模板管理 | LLM调用的Prompt版本化管理 | Prompt变更可回滚；A/B测试支持 |
| F3.2.5 | Token用量追踪 | 记录每次LLM调用的Token消耗 | 按用户/日期统计；成本预警阈值 |

#### F3.3 数据库持久化

**需求描述**：将FlywheelTracker等核心模块的数据从内存存储迁移到数据库

**用户故事**：
> **作为** 多设备使用的用户，
> **我希望** 我的飞轮进度和使用历史能在不同设备间同步，
> **以便** 无论在哪台电脑上都能继续之前的工作。

**功能子项**：

| 子项ID | 名称 | 描述 | 验收标准 |
|--------|------|------|---------|
| F3.3.1 | ORM数据模型 | SQLAlchemy模型定义 | User/FlywheelState/ScenarioRecord/Conversation |
| F3.3.2 | Flywheel持久化 | 飞轮状态读写DB | 重启后数据不丢失；CRUD全覆盖 |
| F3.3.3 | 会话历史存储 | 对话记录完整保存 | 支持分页查询；单用户最多10000条 |
| F3.3.4 | 数据迁移工具 | 内存数据到DB的迁移脚本 | 一键迁移；支持回滚 |
| F3.3.5 | 多租户隔离 | 用户数据严格隔离 | 跨用户数据不可见；权限校验 |

## 三、非功能需求

### 3.1 性能要求

| 指标 | 目标值 | 测量方法 |
|------|--------|---------|
| Web页面首屏加载 | < 2s | Lighthouse |
| API平均响应时间 | < 300ms (P50) | APM监控 |
| API P95响应时间 | < 800ms | APM监控 |
| 并发用户支持 | 100人同时在线 | 压力测试 |
| LLM检测响应 | < 2s (含网络) | 日志统计 |
| 数据库查询 | < 50ms (单表) | EXPLAIN ANALYZE |

### 3.2 安全要求

| 要求 | 具体措施 |
|------|---------|
| 接口认证 | JWT Token + API Key双模式 |
| 数据加密 | 传输TLS 1.3 + 敏感字段AES-256 |
| 输入校验 | 全部API参数Pydantic验证 |
| SQL注入防护 | 仅ORM操作，禁止原始SQL拼接 |
| XSS防护 | 前端输出转义 + CSP头 |
| Rate Limiting | 100请求/分钟/用户 |
| LLM Key安全 | 环境变量存储，禁止硬编码 |

### 3.3 可扩展性

| 维度 | 要求 |
|------|------|
| 水平扩展 | 无状态API层，支持多实例部署 |
| 新平台接入 | 实现PlatformAdapter接口即可 |
| 新LLM后端 | 实现LLMBackend接口即可 |
| 新人格变体 | YAML配置文件即可，无需改代码 |
| 数据库切换 | SQLite(开发) ↔ PostgreSQL(生产) |

### 3.4 可用性要求

| 指标 | 目标 |
|------|------|
| 系统可用性 | 99.5%（计划内维护除外） |
| 数据备份 | 每日自动备份，保留30天 |
| 故障恢复时间 | RTO < 30min |
| 数据丢失容忍 | RPO < 1h |
| 错误日志 | 全量采集，Sentry/自建 |
