## 一、需求背景与三层分析（v3.3修订版）

### 1.1 当前完成状态总览

```

### 1.2 三层需求挖掘（v3.3实际验证版）

**Layer 1: 表面需求（用户说了什么）**
> "帮我写一份Q2营销方案" → 用户要的是**可直接使用的方案文档**
> "帮我收集OPC公司趋势" → 用户要的是**有来源的真实信息**
> "这个文件里面全是___占位符，我能用什么？！" → **用户拒绝空模板**

**Layer 2: 真实需求（用户到底要什么）**
> 用户需要一个**能直接干活的系统**：
> - 输入自然语言 → 系统去搜索/整理/生成 → 返回**可用的成果物文件**
> - 不是建议，不是模板框架，不是"下一步你应该..."
> - 是**已经做完的活**

**Layer 3: 本质需求（为什么）**
> **本质：从"AI助手"进化为"数字员工"**
> - 零学习成本 → 不需要知道怎么提问
> - 零二次加工 → 拿到文件就能用或微调后用
> - 可追溯 → 有来源链接、有时间戳、有版本管理
> - 可复用 → 历史成果物可查看、可重新下载

### v3.5 需求规格

#### F3.5-1: SearchResultProcessor — 搜索结果智能过滤
**用户故事**: 作为一人公司创业者，当我输入业务相关的需求时，系统返回的参考资料应该与我的业务相关，而不是无关内容。

**验收标准 (AC-SEARCH-01)**:
- 输入含特定关键词的query，返回结果中≥60%包含至少一个查询关键词
- 处理耗时 < 100ms（不应增加明显延迟）
- 过滤后结果为空时，返回原始结果（不比v3.4更差）

#### F3.5-2: LLMEnhancedContentGenerator — LLM增强内容生成
**用户故事**: 当我收到生成的方案时，其中的具体指标、时间节点、风险应对应该是针对我的业务的定制化内容，而非放之四海皆准的通用框架。

**验收标准 (AC-CONTENT-01)**:
- 用特定业务背景生成的方案中包含用户的业务关键词
- 无"基准值待测""待填写""此处插入"等占位符
- LLM模式下输出长度 > 2000字符（有实质内容）
- LLM不可用时自动回退到v3.4模板模式（降级不崩溃）

#### F3.5-3: AsyncTaskExecutor — 异步任务执行
**用户故事**: 当我提交一个任务后，我不希望页面卡死或崩溃。我应该看到任务正在处理的状态，并在完成后自动看到结果。

**验收标准 (AC-ASYNC-01)**:
- 提交任务后 < 1s 内看到"已提交"反馈
- 等待过程中页面不崩溃、不断连
- 任务完成后自动展示结果（无需手动刷新）
- 可取消正在运行的任务

#### F3.5-4: SessionContextManager — 多轮对话上下文
**用户故事**: 当我对第一次生成的方案不满意时，我希望能够基于它进行修改和迭代，而不是每次都从头开始。

**验收标准 (AC-ITERATE-01)**:
- 连续3次调用，第2次能引用第1次的结果
- 会话历史限制在20轮以内
- 支持自然语言修改指令："基于上次方案，把第三阶段缩短为2周"

## 四、验收标准（v3.3 SMART版）

### AC-1: 零占位符验收

```
GIVEN 用户输入任意任务
WHEN 系统生成成果物文件
THEN 文件中不包含任何 ___ 或 "待填写" 或 "此处插入"

#### REQ-ARCH-002: 完整反思-重试闭环

| 属性 | 值 |
|------|-----|
| **需求ID** | REQ-ARCH-002 |
| **优先级** | P0 |
| **追溯** | 代码问题 ARCH-02: agent_loop.py 反思脑RETRY/ADJUST被异常吞掉 |
| **用户故事** | 故事9: 完整反思-重试闭环 |

**需求描述**：Plan→Act→Observe→Reflect循环必须支持完整的重试和策略调整。反思脑的RETRY/ADJUST_STRATEGY决策必须真正触发重新执行，而非抛出异常。

**验收标准**：
- AC-ARCH-002-1: RETRY→清空execution_results，从Act阶段重新执行（保留原计划）
- AC-ARCH-002-2: ADJUST_STRATEGY→重新进入Plan阶段，生成新计划后重新执行
- AC-ARCH-002-3: CONTINUE→结果符合预期，正常完成
- AC-ARCH-002-4: ABANDON→清晰说明原因，设置状态为FAILED
- AC-ARCH-002-5: REVIEW→暂停循环，等待人工介入
- AC-ARCH-002-6: 反思循环最多`MAX_REFLECT_ROUNDS`轮（默认3），防止无限循环
- AC-ARCH-002-7: 每轮反思结果记录到执行日志

**行为规格（状态机）**：
```
PLAN → ACT → OBSERVE → REFLECT →
  ├─ CONTINUE → COMPLETED
  ├─ RETRY → ACT（清空结果，保留计划）
  ├─ ADJUST_STRATEGY → PLAN → ACT → OBSERVE → REFLECT
  ├─ REVIEW → COMPLETED（标记需人工复核）
  └─ ABANDON → FAILED
（最多循环3轮，超出后自动COMPLETED并标记"反思循环已达上限"）
```
