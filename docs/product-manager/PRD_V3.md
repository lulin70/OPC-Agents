## 一、需求背景与三层分析（v3.3修订版）

### 1.1 当前完成状态总览

```
✅ 已完成 (v3.3):
├── TaskEngineV3 (意图分类 → 真实搜索 → 结构化生成 → 文件交付)
├── WebSearchMCP (DuckDuckGo实时搜索，8条结果/请求)
├── Streamlit前端 (对话界面 + 成果物管理 + 下载功能)
├── ScenarioEngineV2 (9个预设场景工作流)
├── BusinessTypeDetectorV2 (6种业务类型自动检测)
├── PersonaManager (6种人格配置)
├── FlywheelTracker (五维成长飞轮)
├── deliverables/ (成果物持久化存储)
└── 400+ 测试用例
```

### 1.2 三层需求挖掘（v3.3实际验证版）

**Layer 1: 表面需求（用户说了什么）**
> "帮我写一份Q2营销方案" → 用户要的是**可直接使用的方案文档**
> "帮我收集OPC公司趋势" → 用户要的是**有来源的真实信息**
> "这个文件里面全是___占位符，我能用什么？！" → **用户拒绝空模板**

**Layer 2: 真实需求（用户到底要什么）**
> 用户需要一个**能直接干活的系统**：
> - 输入自然语言 → 系统去搜索/整理/生成 → 返回**可用的成果物文件**
> - 不是建议，不是模板框架，不是"下一步你应该..."
> - 是**已经做完的活**

**Layer 3: 本质需求（为什么）**
> **本质：从"AI助手"进化为"数字员工"**
> - 零学习成本 → 不需要知道怎么提问
> - 零二次加工 → 拿到文件就能用或微调后用
> - 可追溯 → 有来源链接、有时间戳、有版本管理
> - 可复用 → 历史成果物可查看、可重新下载

## 四、验收标准（v3.3 SMART版）

### AC-1: 零占位符验收

```
GIVEN 用户输入任意任务
WHEN 系统生成成果物文件
THEN 文件中不包含任何 ___ 或 "待填写" 或 "此处插入"
AND  文件中不包含 "清晰定义目标" 或 "明确边界" 等废话框架
```

### AC-2: 文件交付验收

```
GIVEN 用户执行一个任务
WHEN 任务处理完成
THEN deliverables/ 目录下生成对应的 .md 文件
AND 页面上显示下载按钮
AND 点击下载按钮可获得完整文件内容
```

### AC-3: 真实搜索验收

```
GIVEN 用户输入信息收集类任务（如"收集XX趋势"）
WHEN 系统处理完成
THEN 结果包含来自 DuckDuckGo 的真实搜索结果
AND 每条结果有标题、摘要和来源链接
AND 搜索结果数量 >= 3 条
```

### AC-4: 方案文档质量验收

```
GIVEN 用户输入"帮我写XX方案"
WHEN 系统生成方案文档
THEN 文档包含以下全部要素:
  - 项目概览表（名称/日期/周期）
  - SMART目标（含具体指标如"提升30%"、"≥95%"）
  - 分阶段实施路线图（含具体时间和负责人角色）
  - 资源配置表
  - 风险管理矩阵（每项风险有具体描述和应对措施）
  - 验收标准清单（每项可检查）
AND 以上所有要素不含空占位符
```
