## 1. 产品目标

### 1.1 版本目标

将 OPC-Agents 从**被动响应式任务执行系统**升级为**可持续主动执行的 OPC 运营助手**：

> 用户配置一次业务规则，系统持续维护客户关系、识别跟进机会、执行经确认的任务，并在关键决策处让用户掌控。

### 1.2 用户价值

| 用户问题 | v1.0.0 解法 | 可验证指标 |
|---------|-----------|-----------|
| 客户信息散落、无法统一管理 | CRM + PromiseLink 实体/关系能力 | 客户可查询率 100% |
| 线索和客户容易忘记跟进 | 沉默客户扫描 + 承诺/提醒 + 跟进队列 | 到期跟进发现率 ≥95% |
| 重复工作占据大量时间 | 定时任务 + 报告/早报自动生成 | 自动完成配置任务 ≥90% |
| 自动化误发邮件或误操作 | 三贤者 + 关键决策点 fail-close | 未确认不可逆操作执行率 0% |
| 系统越用越不懂业务 | CarryMem 偏好/规则记忆 | 跨会话偏好命中可验证 |

### 1.3 非目标

v1.0.0 不包含：

- 全量营销自动化或保证获客结果
- 自动发送未经用户确认的外部商务邮件
- 取代会计、律师或财税专业人员
- 完整多平台内容发布（v1.1.0）
- MCP 技能商业市场和结算（v2.0.0）
- PromiseLink 源码复制或数据库合并

## 2. 目标用户与场景

### 2.1 优先用户

v1.0.0 优先服务：

1. 咨询顾问和独立服务商
2. 小型 B2B 产品创始人
3. 电商/工作室经营者
4. 有明确客户跟进需求的自由职业者

### 2.2 核心用户故事

#### US-CRM-01 客户管理

> 作为 OPC 经营者，我想从会议记录或名片信息中自动建立客户档案，以便不重复录入。

验收：输入事件后，系统创建/更新实体；重复实体需提示确认，不得静默覆盖。

#### US-CRM-02 客户关系视图

> 作为 OPC 经营者，我想看到某客户的最近互动、待兑现承诺、风险、下一步建议，以便决定是否跟进。

验收：客户详情展示 PromiseLink 关系推进卡聚合视图；外部服务不可用时明确显示数据来源/降级状态。

#### US-LEAD-01 线索识别

> 作为 OPC 经营者，我想从咨询记录中识别潜在线索、合作信号和风险，以便优先处理高价值机会。

验收：事件管线生成结构化 Todo；低置信度结果进入待确认队列。

#### US-FOLLOW-01 对方承诺跟进

> 作为 OPC 经营者，我想知道客户答应的事情是否到期，以便温和地提醒对方。

验收：展示 my/their 双视角承诺、履约状态、到期时间；催促仅生成草稿，不自动发送。

#### US-FOLLOW-02 客户跟进序列

> 作为 OPC 经营者，我想为已确认客户配置 Day 3/7/14 跟进，以便减少遗忘。

验收：任务按日期进入队列；受静默时段、每日疲劳阈值和人工暂停控制。

#### US-SCHEDULE-01 主动任务

> 作为 OPC 经营者，我想配置“每周一生成营销周报”等定时任务，以便在打开应用前完成准备工作。

验收：重启后任务不丢失；每次执行有状态、结果和审计记录；失败不会绕过保护门禁。

#### US-REPORT-01 经营早报

> 作为 OPC 经营者，我想每天收到沉默客户、到期承诺、今日事件和待办摘要，以便快速安排当天工作。

验收：摘要数据可追溯到源事件/实体/Todo；无数据时显示 0 或空状态，不生成虚假结论。

#### US-DATA-01 数据控制

> 作为 OPC 经营者，我想导出、删除和控制客户数据，以便满足数据可携带和隐私要求。

验收：导出和删除需明确确认；Token、PII 不写入普通日志；失败可重试且有审计记录。

## 4. 业务规则

### 4.1 自动化边界

1. GREETING/SIMPLE/COMPLEX 路由规则维持现状。
2. 涉及 email、finance、report 的自动任务必须经过关键决策点保护。
3. 任何外部发送默认只生成草稿；用户确认后才发送。
4. PromiseLink 只提供关系数据和建议，不拥有 OPC-Agents 的发送权限。
5. PromiseLink API 不可用时，不能阻塞 CRM 本地浏览和已有任务执行。

### 4.2 跟进规则

1. 只有已确认的客户实体进入自动跟进候选。
2. `their_promise` 到期后优先生成草稿，不自动发送。
3. 遵守每日疲劳阈值和 22:00-08:00 静默时段。
4. 同一实体存在多个待跟进项时合并展示，避免重复打扰。
5. 用户标记完成/忽略/暂停后，自动任务不得覆盖人工决定。

### 4.3 数据规则

1. PromiseLink 与 OPC-Agents 数据库保持独立。
2. 关联采用外部实体 ID 映射，不复制全部原始 PII。
3. 所有外部响应必须标记 `source=promiselink` 或 `source=local_fallback`。
4. Token 不进入日志、报告、错误消息和导出文件。

## 5. v1.0.0 验收标准

### 必须满足

- [ ] CRM P0 需求全部可通过 UI 和 API 完成
- [ ] 客户输入→实体→关系卡→跟进队列闭环可运行
- [ ] 定时任务重启后恢复，执行历史完整
- [ ] email/report/finance 关键任务无法绕过共识保护
- [ ] PromiseLink 不可用时本地核心能力继续可用
- [ ] 真实 PromiseLink 实例 smoke 测试通过（发布前）
- [ ] 真实用户浏览器旅程 E2E 通过（发布前）
- [ ] 安全、隐私、限流、审计测试通过
- [ ] 现有门禁不回退，覆盖率不低于当前 CI 阈值

### 不接受

- 用 Mock 单元测试替代真实 API/浏览器 E2E
- 用 skip 隐藏失败
- 使用未经 PromiseLink 源码确认的路由
- 在无用户确认时发送外部邮件
- 把规划中的增强接口描述成已实现接口
