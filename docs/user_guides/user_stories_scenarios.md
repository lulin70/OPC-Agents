## 一、核心用户故事

### 故事 1：智能化一人公司运营

**角色**: OPC 公司唯一员工（用户）

**场景**: 周一上午 9:00，用户同时处理多个任务，系统智能辅助

```
用户目标：
- 同时进行市场分析、消息监控、产品方案讨论
- 不需要等待一个任务完成再开始下一个
- 可以随时查看各个任务的进度
- 紧急任务自动优先处理
- 任务失败时系统自动决策重试或报告
- 不在电脑前时也能收到重要通知
```

**痛点**:
- 以前只能串行执行任务，效率低
- 无法同时处理多个业务需求
- 紧急任务需要等待当前任务完成
- 任务失败需要手动处理
- 离开座位就错过重要通知

**解决方案**:
- ✅ 多任务并发管理系统
- ✅ 不同 Agent 可以同时执行任务
- ✅ 优先级调度确保紧急任务优先
- ✅ 实时监控面板显示所有任务进度
- ✅ 智能错误分类与自动重试
- ✅ 四级通知系统（紧急/重要/普通/低）
- ✅ 调度透明化（思考过程可视化）
- ✅ 资源监控与优化建议

## 二、详细使用场景

### 场景 1：并发任务执行

**时间**: 周一 9:00 AM

**任务列表**:
1. **市场分析** (Market Dept Agent)
   - 优先级：中 (5)
   - 内容：搜索竞品动态，生成分析报告
   - 预计时长：30 分钟

2. **消息监控** (Monitor Dept Agent)
   - 优先级：高 (8)
   - 内容：监控邮件、微信、钉钉新消息
   - 预计时长：持续运行

3. **产品方案讨论** (Three Sages Agent)
   - 优先级：高 (9)
   - 内容：与三贤者讨论新产品方案
   - 预计时长：15 分钟

4. **数据备份** (IT Dept Agent)
   - 优先级：低 (3)
   - 内容：备份重要数据到云存储
   - 预计时长：5 分钟

**执行流程**:
```
9:00 AM - 用户提交 4 个任务
  ↓
9:00 AM - 任务调度器接收任务
  ├─ 产品方案讨论 (优先级 9) → 立即启动
  ├─ 消息监控 (优先级 8) → 立即启动
  ├─ 市场分析 (优先级 5) → 等待队列
  └─ 数据备份 (优先级 3) → 等待队列
  ↓
9:00 AM - Three Sages 和 Monitor Dept 开始执行
  ↓
9:01 AM - 用户调整数据备份优先级为高 (8)
  ↓
9:01 AM - 数据备份任务插队，等待 Market Dept 空闲
  ↓
9:15 AM - 产品方案讨论完成
  ├─ Three Sages 变为空闲
  ├─ 从队列获取下一个任务
  └─ 开始执行市场分析
  ↓
9:30 AM - 所有任务完成
```

**用户操作**:
```python
# 提交任务
manager.submit_task('task_001', '产品方案讨论', 'three_sages', priority=9)
manager.submit_task('task_002', '消息监控', 'monitor_dept', priority=8)
manager.submit_task('task_003', '市场分析', 'market_dept', priority=5)
manager.submit_task('task_004', '数据备份', 'it_dept', priority=3)

# 调整优先级
manager.update_task_priority('task_004', 8)

# 查看状态
status = manager.get_all_tasks_status()
print(f"运行中：{status['total_running']}")
print(f"队列中：{status['total_queue']}")
```

### 场景 3：智能错误处理与自动重试

**时间**: 周三 10:00 AM

**场景描述**:
用户提交了一个网页搜索任务，但网络不稳定导致超时。系统智能分类错误并自动重试。

**系统行为**:
```
10:00 AM - 提交网页搜索任务 (超时：30 秒)
  ↓
10:00 AM - 任务开始执行
  ↓
10:00:30 AM - 30 秒后未完成，触发超时
  ↓
10:00:30 AM - 错误分类器识别为"网络超时"（可自动重试）
  ↓
10:00:30 AM - 系统自动重试 (延迟 2 秒，指数退避)
  ↓
10:00:32 AM - 重试执行 (第 1 次)
  ↓
10:01:02 AM - 再次超时
  ↓
10:01:02 AM - 系统自动重试 (延迟 4 秒，指数退避)
  ↓
10:01:06 AM - 重试执行 (第 2 次)
  ↓
10:01:20 AM - 任务成功完成
```

**错误分类示例**:
```python
# 1. 网络超时 → 自动重试（最多 3 次）
ErrorCategory.RETRYABLE_AUTO: "网络超时、API 限流"

# 2. 资源不足 → 建议重试（用户确认）
ErrorCategory.RETRYABLE_ADVISED: "内存不足、依赖缺失"

# 3. 代码 bug → 停止执行（需要人工干预）
ErrorCategory.NON_RETRYABLE: "代码 bug、权限不足"

# 4. 高风险 → 等待指示
ErrorCategory.HIGH_RISK: "付费 API 失败、数据丢失风险"
```

**配置**:
```python
manager.submit_task(
    task_id='search_001',
    task_name='网页搜索',
    agent='web_search',
    timeout_seconds=30,  # 30 秒超时
    max_retries=3,       # 最多重试 3 次
    retry_delay=2        # 初始延迟 2 秒
)
```

### 场景 4：智能通知分级系统

**时间**: 周四 3:00 PM

**场景描述**:
用户不在电脑前，系统根据通知级别通过不同渠道发送通知。

**系统行为**:
```
3:00 PM - 用户提交任务后离开办公室
  ↓
3:15 PM - 任务完成（P1 重要通知）
  ↓
3:15 PM - 通知系统检查用户偏好
  ├─ 免打扰时段？否（当前 15:00）
  ├─ 通知级别？P1_Important
  └─ 发送渠道？站内消息 + 邮件
  ↓
3:15 PM - 发送通知
  ├─ 站内消息：任务完成通知
  └─ 邮件：详细结果报告
  ↓
10:00 PM - 后台任务完成（P3 低优先级）
  ↓
10:00 PM - 通知系统判断
  ├─ 免打扰时段？是（22:00-08:00）
  └─ 处理方式：暂不发送，加入每日汇总
  ↓
次日 08:00 AM - 发送每日汇总报告
```

**通知级别**:
```python
# P0 紧急通知 - 任务失败需立即决策
NotificationLevel.P0_URGENT: "任务失败需决策"
  → 渠道：站内 + 邮件 + 微信（实时）

# P1 重要通知 - 用户等待的任务完成
NotificationLevel.P1_IMPORTANT: "任务完成（用户等待）"
  → 渠道：站内 + 邮件

# P2 普通通知 - 非紧急任务完成
NotificationLevel.P2_NORMAL: "任务完成（非紧急）"
  → 渠道：每日汇总报告

# P3 低优先级 - 后台任务
NotificationLevel.P3_LOW: "后台任务"
  → 渠道：不通知（可查询）
```

**用户偏好配置**:
```python
preferences = NotificationPreferences(
    quiet_hours_start=22,      # 22:00 开始免打扰
    quiet_hours_end=8,         # 08:00 结束
    email_notifications=True,   # 启用邮件通知
    wechat_notifications=True,  # 启用微信通知
    min_notify_level='p1'       # 最小通知级别
)
```

### 场景 5：优先级智能推荐

**时间**: 周五 9:00 AM

**场景描述**:
用户提交多个任务但不确定优先级，系统智能推荐。

**系统行为**:
```
9:00 AM - 用户提交 3 个任务
  ├─ 任务 1: "回复客户咨询邮件" (未指定优先级)
  ├─ 任务 2: "市场调研报告" (未指定优先级)
  └─ 任务 3: "整理内部文档" (未指定优先级)
  ↓
9:00 AM - 优先级智能推荐系统分析
  ↓
9:00 AM - 推荐结果
  ├─ 任务 1: 推荐 HIGH (9) - 客户邮件（业务价值 30 分）+ 无依赖
  ├─ 任务 2: 推荐 MEDIUM (5) - 市场调研（业务价值 20 分）
  └─ 任务 3: 推荐 LOW (3) - 文档整理（业务价值 15 分）
  ↓
9:00 AM - 用户确认推荐
  ↓
9:01 AM - 任务按推荐优先级开始执行
```

**评分算法**:
```python
# 总分 100 分 = 截止时间 40% + 依赖关系 30% + 业务价值 30%

deadline_score = 40  # 今天截止=40，明天=20，本周=10
dependency_score = 30  # 有依赖=30，无依赖=0
business_value = 30  # 客户邮件=30，市场调研=20，文档=15

total_score = 40 + 30 + 30 = 100 → Priority.HIGH
```

**业务价值库**:
```python
BUSINESS_VALUE_SCORES = {
    'customer_email': 30,      # 客户邮件 - 高价值
    'market_research': 20,     # 市场调研 - 中价值
    'documentation': 15,       # 文档 - 中低价值
    'internal_meeting': 10,    # 内部会议 - 低价值
```

## 四、技术特性

### 并发模型
- ✅ **多 Agent 并发**: 不同 Agent 可以同时执行任务
- ✅ **线程池管理**: 高效的任务执行
- ✅ **资源隔离**: 任务间互不影响

### 调度策略
- ✅ **优先级队列**: 基于优先级的任务调度
- ✅ **公平调度**: 同优先级按提交时间排序
