## 一、核心用户故事

### 故事 1：一人公司的日常

**角色**: OPC 公司唯一员工（用户）

**场景**: 周一上午 9:00，用户同时处理多个任务

```
用户目标：
- 同时进行市场分析、消息监控、产品方案讨论
- 不需要等待一个任务完成再开始下一个
- 可以随时查看各个任务的进度
- 紧急任务可以优先处理
```

**痛点**:
- 以前只能串行执行任务，效率低
- 无法同时处理多个业务需求
- 紧急任务需要等待当前任务完成

**解决方案**:
- 多任务并发管理系统
- 不同 Agent 可以同时执行任务
- 优先级调度确保紧急任务优先
- 实时监控面板显示所有任务进度

## 二、详细使用场景

### 场景 1：并发任务执行

**时间**: 周一 9:00 AM

**任务列表**:
1. **市场分析** (Market Dept Agent)
   - 优先级：中 (5)
   - 内容：搜索竞品动态，生成分析报告
   - 预计时长：30 分钟

2. **消息监控** (Monitor Dept Agent)
   - 优先级：高 (8)
   - 内容：监控邮件、微信、钉钉新消息
   - 预计时长：持续运行

3. **产品方案讨论** (Three Sages Agent)
   - 优先级：高 (9)
   - 内容：与三贤者讨论新产品方案
   - 预计时长：15 分钟

4. **数据备份** (IT Dept Agent)
   - 优先级：低 (3)
   - 内容：备份重要数据到云存储
   - 预计时长：5 分钟

**执行流程**:
```
9:00 AM - 用户提交 4 个任务
  ↓
9:00 AM - 任务调度器接收任务
  ├─ 产品方案讨论 (优先级 9) → 立即启动
  ├─ 消息监控 (优先级 8) → 立即启动
  ├─ 市场分析 (优先级 5) → 等待队列
  └─ 数据备份 (优先级 3) → 等待队列
  ↓
9:00 AM - Three Sages 和 Monitor Dept 开始执行
  ↓
9:01 AM - 用户调整数据备份优先级为高 (8)
  ↓
9:01 AM - 数据备份任务插队，等待 Market Dept 空闲
  ↓
9:15 AM - 产品方案讨论完成
  ├─ Three Sages 变为空闲
  ├─ 从队列获取下一个任务
  └─ 开始执行市场分析
  ↓
9:30 AM - 所有任务完成
```

**用户操作**:
```python
# 提交任务
manager.submit_task('task_001', '产品方案讨论', 'three_sages', priority=9)
manager.submit_task('task_002', '消息监控', 'monitor_dept', priority=8)
manager.submit_task('task_003', '市场分析', 'market_dept', priority=5)
manager.submit_task('task_004', '数据备份', 'it_dept', priority=3)

# 调整优先级
manager.update_task_priority('task_004', 8)

# 查看状态
status = manager.get_all_tasks_status()
print(f"运行中：{status['total_running']}")
print(f"队列中：{status['total_queue']}")
```

### 场景 2：任务暂停与恢复

**时间**: 周二 2:00 PM

**场景描述**:
用户正在进行产品方案讨论，突然接到重要电话，需要暂停任务。

**操作流程**:
```
2:00 PM - 产品方案讨论正在进行中 (进度 30%)
  ↓
2:01 PM - 用户暂停任务
  ↓
2:01 PM - 任务进入暂停状态
  ├─ Three Sages Agent 变为空闲
  └─ 可以执行其他任务
  ↓
2:30 PM - 用户返回，恢复任务
  ↓
2:30 PM - 任务从 30% 进度继续执行
  ↓
2:45 PM - 任务完成
```

**用户操作**:
```python
# 暂停任务
manager.pause_task('task_001')

# 查看状态
status = manager.get_task_status('task_001')
print(status['status'])  # 'paused'
print(status['progress'])  # 30

# 恢复任务
manager.resume_task('task_001')
```

### 场景 3：任务超时与重试

**时间**: 周三 10:00 AM

**场景描述**:
用户提交了一个网页搜索任务，但网络不稳定导致超时。

**系统行为**:
```
10:00 AM - 提交网页搜索任务 (超时：30 秒)
  ↓
10:00 AM - 任务开始执行
  ↓
10:00:30 AM - 30 秒后未完成，触发超时
  ↓
10:00:30 AM - 系统自动重试 (延迟 2 秒)
  ↓
10:00:32 AM - 重试执行 (第 1 次)
  ↓
10:01:02 AM - 再次超时
  ↓
10:01:02 AM - 系统自动重试 (延迟 4 秒，指数退避)
  ↓
10:01:06 AM - 重试执行 (第 2 次)
  ↓
10:01:20 AM - 任务成功完成
```

**配置**:
```python
manager.submit_task(
    task_id='search_001',
    task_name='网页搜索',
    agent='web_search',
    timeout_seconds=30,  # 30 秒超时
    max_retries=3,       # 最多重试 3 次
    retry_delay=2        # 初始延迟 2 秒
)
```

### 场景 4：事件通知

**时间**: 周四 3:00 PM

**场景描述**:
用户注册了任务完成事件回调，当任务完成时自动收到通知。

**系统行为**:
```
3:00 PM - 用户注册事件回调
  ↓
3:01 PM - 提交任务
  ↓
3:01 PM - 触发 task_submitted 事件
  ├─ 记录日志
  └─ 发送通知
  ↓
3:02 PM - 任务开始执行
  ↓
3:02 PM - 触发 task_started 事件
  ├─ 更新 UI
  └─ 发送进度通知
  ↓
3:15 PM - 任务完成
  ↓
3:15 PM - 触发 task_completed 事件
  ├─ 记录结果
  ├─ 发送完成通知
  └─ 添加到历史记录
```

**用户操作**:
```python
def on_task_complete(task):
    print(f"任务完成：{task.task_name}")
    # 发送邮件通知
    send_email(f"任务 {task.task_name} 已完成")

def on_task_failed(task):
    print(f"任务失败：{task.task_name} - {task.error}")
    # 发送失败通知
    send_alert(f"任务 {task.task_name} 失败：{task.error}")

manager.register_event_callback('task_completed', on_task_complete)
manager.register_event_callback('task_failed', on_task_failed)
```

## 三、用户价值

- **自动重试**: 失败任务自动重试，提高成功率

### 透明可见
- **实时监控**: 清楚知道每个任务的状态

## 四、技术特性

### 并发模型
- **多 Agent 并发**: 不同 Agent 可以同时执行任务
- **线程池管理**: 高效的任务执行
- **资源隔离**: 任务间互不影响

### 调度策略
- **优先级队列**: 基于优先级的任务调度
- **公平调度**: 同优先级按提交时间排序
- **动态调整**: 支持运行时调整优先级

### 容错机制
- **超时控制**: 防止任务无限期运行
- **自动重试**: 失败任务自动重试（指数退避）
- **错误处理**: 完善的错误处理和日志记录

### 可观测性
- **事件系统**: 丰富的事件回调
- **状态跟踪**: 完整的任务状态管理
- **资源监控**: 实时系统资源监控
